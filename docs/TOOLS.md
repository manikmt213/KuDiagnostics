# KuDiagnostics — tool reference

Generated by `node scripts/tool-reference.mjs` from the tools registered in the plugin. Do not edit by hand.

424 tools. Scope: `kuduy:read` ⊂ `kuduy:write` ⊂ `kuduy:admin`; `kuduy:code` is separate and exists only with `KUDUY_MCP_ALLOW_CODE_EXEC`. Every tool also checks the WordPress capability of the signed-in user, per object. Tools of plugins that are not active are not listed to Claude.

## Core

### `kuduy-site-info` — Site info

Returns the site name, URL, language, timezone, WordPress and KuDiagnostics versions, active theme, and the connected WordPress user with their roles. Call this first to learn what site you are working on.

Scope `kuduy:read` · read only

No input.

### `kuduy-integrations` — Supported builders, themes and plugins

Says what KuDiagnostics can do with the page builders, themes and plugins on this site: for each one whether it is installed and active, how far it is supported (full, partial, detection only, none), which tools manage it and whether they are available now, and what is not covered. By default only what is installed here; all: true lists the whole catalogue. Filter with category or search. Call this before working with a builder, theme or plugin you have not used on this site.

Scope `kuduy:read` · read only

### `kuduy-integration-get` — One integration in detail

Returns one builder, theme or plugin from kuduy-integrations in detail: installed, active, version, how far it is supported, whether a free copy exists, what it needs (e.g. an add-on needs Elementor) and the state of those, and every tool that manages it — name, title, read-only or changing, destructive, needed access level, and whether it can be called right now (or why not). include_schemas: true adds each tool's input schema. ### `kuduy-integration-diagnose` — Diagnose integrations

Checks the integrations installed on this site (or one, with integration) and lists what stands in the way of using them: installed but not active, a required plugin or theme missing or inactive, tools that cannot run and why, products whose support was not verified against the real product, and products that are only recognised. Each finding has a level (error, warning, info). Read only; nothing is changed.

Scope `kuduy:read` · read only

| Input | Type | Required | Notes |
|---|---|---|---|
| `integration` | string |  | Integration id from kuduy-integrations, e.g. "elementor" or "woocommerce". |

### `kuduy-design-scan` — Scan the site design

Collects the site's design tokens in one place, each with where it is set: colors (theme palette, page background and text, link color, Elementor Kit colors, Customizer colors), fonts and font sizes (theme and Elementor Kit), spacing sizes and layout widths, plus the site name, tagline, logo and icon. Use it before designing or changing pages so new work matches; the summary can be saved with kuduy-memory-save (kind "design"). Reads only.

Scope `kuduy:read` · read only

No input.

The copy is never published. Elementor pages: use kuduy-elementor-duplicate. WooCommerce products are refused. Undo: kuduy-post-trash on the copy.
